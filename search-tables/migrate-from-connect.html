Moving a CQL search macro from a Connect app to Forge

Atlassian has announced that support for the Connect app framework ends on 31 January 2027 (announcement). After that date Connect apps are no longer maintained by the platform, and Atlassian warns that breakages will increase. If your Confluence pages rely on a Connect-based macro that embeds search results, this guide shows how to move those tables to Search Tables, which is built on Forge.

Not sure whether an app is on Connect? Its Marketplace listing and the app's entry in your site's app management page show how it is hosted. An app that already "Runs on Atlassian" or is listed as a Forge app is not affected.

Step 1 – List the pages that use the old macro

You need the name of the old macro as Confluence stores it. Take one page that uses it, note its page ID (the number in the page URL) and open https://YOUR-SITE.atlassian.net/wiki/plugins/viewstorage/viewpagestorage.action?pageId=PAGE_ID. In the text that appears, look for the macro's ac:name="…" value. (The same view is available from the page's ••• menu as View storage format on sites that show it.)

Then install Search Tables, add it to a scratch page, open the CQL tab and run:

macro = "old-macro-name" ORDER BY title

The result is your migration checklist; add the Space column to see where each page lives. Press Export CSV to keep it in a spreadsheet. If the query returns nothing, the macro name is probably different from what you typed; as a fallback, search for a word that all those pages share.

Step 2 – Rebuild each table

  1. Edit the page, type /Search Tables and press Enter.
  2. If the old macro used a CQL query, paste the same query into the CQL tab. Otherwise rebuild it with the Filters tab (spaces, labels, content types, dates, parent page).
  3. Pick the columns, the default sort and the rows per page. The preview shows the live result.
  4. Save, compare with the old table, then remove the old macro from the page.

Step 3 – Keep recurring queries as shared saved searches

If the same query appears on many pages, save it once as a shared saved search and load it into the other tables. When the shared search changes, synced tables follow.

Step 4 – Finish

When every page on the checklist is done, run the query from step 1 again. An empty result means no page uses the old macro any more, and the old app can be uninstalled.

What to expect

  • Search Tables shows results as a table with sorting, paging and CSV export. Layout and options will not be identical to your old macro.
  • Every search runs with the permissions of the person viewing the page.
  • The app stores only saved searches (name, query, owner). It uses no external servers, and no data leaves Atlassian.
  • If your old macro had a feature you depend on and you cannot find it here, tell us at datadocklabs@gmail.com before you migrate.
