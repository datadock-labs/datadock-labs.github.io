How to list pages with a label but leave out the current page

Short answer: add AND id != currentContent() to a label search. currentContent() means "the page this table is on", so a "related pages" list built from a label no longer shows the page you are already reading. The built-in Content by Label macro has no such option; in a Search Tables macro it is one extra condition in the CQL tab.

Search Tables is a new Confluence Cloud app and is coming soon to the Atlassian Marketplace (it is in Atlassian's review now). The steps below describe what the app does today.

The query

Other pages with the label onboarding, newest first:

type = page AND label = "onboarding" AND id != currentContent() ORDER BY created DESC

Only in this space, and matching two labels at once:

type = page AND space = currentSpace() AND label = "onboarding" AND label = "checklist" AND id != currentContent() ORDER BY title

Leave out a different, fixed page by its ID (the number in the page URL):

type = page AND label = "onboarding" AND id != 123456

Step by step

  1. Edit the page, type /Search Tables and switch to the CQL tab. (The Filters tab can build the label part, but excluding a page needs CQL.)
  2. Paste the first query and change the label name.
  3. For a compact "related pages" box choose only the Title and Last modified columns and 10 rows per page.
  4. Save. If the page is used as a template for new pages with the same label, every copy shows the others but not itself.

Checked on a Confluence Cloud test site in November 2026: a label shared by 120 pages returned 119 results with id != currentContent(), and the current page was not among them.

Compared with what Confluence offers built in

  • Content by Label: simple and fine when listing the current page does not bother you. It cannot leave the current page out; that is an open request in Atlassian's public tracker: CONFCLOUD-5245.
  • Search Tables: needs one line of CQL, and in return you choose the columns, sort across the whole result and can export the list to CSV.

FAQ

Does currentContent() work everywhere? It works in a table placed on a page or blog post, because the table knows which page it is on. On the app's own Search Tables page in the Apps menu there is no current page, so use a fixed id != 123456 there.

Can I leave out several pages? Yes: id not in (123456, 234567).

Can I also leave out child pages? Yes, if they sit under one parent: add AND ancestor != 123456 with the parent page's ID. Test it in the live preview before saving.

Will readers see pages they cannot open? No. Every search runs with the reader's own permissions.
