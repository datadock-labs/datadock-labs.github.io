Search Tables and Confluence's built-in report macros

Confluence Cloud ships with report macros such as Content by Label, Page Properties Report and Task Report. They are a good fit for simple lists, and you should use them when they are enough. Search Tables is for the cases where you need a real table of search results: columns you choose, sorting across the whole result, paging, saved searches and CSV export.

This page is deliberately plain about what Search Tables does today and what it does not do.

What Search Tables does today

  • Shows the result of any Confluence search as a table on a page: simple filters or CQL.
  • Filters: text, title, one or more spaces (including "current space"), content types (pages, blog posts, comments, attachments, whiteboards, databases, folders), labels (any or all), created or edited by me, last modified (presets or a date range), and pages under a parent page.
  • Columns you pick: title, type, space, created by, created, last modified, modified by, labels.
  • Sorting by title, created or last modified across the whole result, not just the visible rows; 10, 25, 50 or 100 rows per page.
  • Saved searches, personal or shared with the whole site, reusable in any table.
  • CSV export of up to 2,000 rows.
  • Every search runs with the viewer's own permissions; no data leaves Atlassian.

Open requests in Atlassian's public tracker, and where Search Tables stands

When the built-in macros are the better choice

  • You only need a short list of pages with a label: Content by Label is simpler.
  • You need a report built from Page Properties tables: use Page Properties Report today.
  • You need a list of tasks: use Task Report.
